### 2026-07-11 (Task 2: Run example fit; update workflow document to v0.2)

Ran `run_alis fit_spectra.mod` on the simplest ALIS example
(`examples/metal_line_abs/`). Examined the input data file, the `.mod.out`
output, and the `_fit.dat` output data file. Updated `doc/ALIS_workflow.md`
to version 0.2.

**What was run:**

- Generated data file: `examples/metal_line_abs/data/OI_SiII.dat` (554 rows,
  4 columns: wavelength, noisy flux, 1σ error, noiseless model). Data were
  previously generated by `generate_spectra.mod` with known true parameters.
- Fit model: `examples/metal_line_abs/model/fit_spectra.mod` — fits a Legendre
  continuum + O I 1302 Å + Si II 1304 Å Voigt profiles.
- Output model: `fit_spectra.mod.out` — records best-fit χ²=385.3, DOF=360,
  reduced χ²=1.070, 10 iterations.
- Output data: `OI_SiII_fit.dat` (392 rows, 4 columns: wavelength, flux, error,
  best-fit model; 24 rows outside `fitrange` carry sentinel value −9.999999999×10⁹).

**Key finding — local minimum:**

The fit converged to an incorrect solution: O I log N=16.5 (true: 14.0),
b_turb=0.5 km/s (true: 5.0 km/s), yet reduced χ²≈1.07. This illustrates a
fundamental challenge in Voigt profile fitting: a highly saturated, narrow line
and a moderately saturated, broader line can produce indistinguishable residuals
at a given spectral resolution. The b-parameter initial guess (0.5 km/s) drove
the fit into this local minimum. The `fit_spectra_linear.mod` variant, which
starts at b=5.0 km/s, recovers the true parameters.

### 2026-07-12 (Task 3: Re-run example fit after bug fix; update workflow doc to v0.3)

Re-ran `run_alis fit_spectra.mod` after the user corrected a bug in
`fit_spectra.mod`. The bug was that the starting b-parameter was 0.5 km/s
(much too small relative to the true value of 5.0 km/s), which caused the
Task 2 fit to converge to a degenerate local minimum.

**The fix:** Starting b-parameter changed from `0.5da` to `1.0da`. This was
sufficient for the minimizer to escape the local minimum and find the correct
global solution.

**Corrected fit results (fit_spectra.mod.out):**

- Initial χ² = 485.0, best-fit χ² = 355.8, DOF = 360, reduced χ² = 0.988
- 6 iterations to convergence
- O I: log N = 13.989 ± 0.017 (true: 14.0) — within 0.7σ
- Si II: log N = 12.933 ± 0.060 (true: 13.0) — within 1.1σ
- b_turb = 4.633 ± 0.355 km/s (true: 5.0) — within 1σ

Residuals (data − model)/σ: mean = 0.000, std = 0.983 — consistent with white noise.

**PDF output (`fit_spectra.pdf`):** One panel showing the spectrum (black) with
best-fit model (red) and continuum (blue dashed). Both O I 1302 and Si II 1304
absorption troughs are well traced by the model. The lower sub-panel shows
residuals centred on zero, within the ±1σ band, with no visible systematics.

**Updated `doc/ALIS_workflow.md` to v0.3:**

- Updated §4.1 fit statistics and best-fit parameter table with corrected results
- Added §4.1.1 describing the PDF plot layout (upper spectrum + lower residuals panels)
- Added §4.1.2 explaining the local minimum from the original (bugged) run and the
  importance of b-parameter starting values in Voigt profile fitting

### 2026-10-03 (Expand §0 "Prepare fitting regions"; update workflow doc to v0.4)

Expanded RJC's new §0 of `doc/ALIS_workflow.md` from the `prepfit` source
(`alis/prepfit/specplot.py`), `examples/prepfit/`, and the snips and data blocks
in `context/fitting_examples/`. Added §0.1–0.6: the snip file format and
naming, setting up `prepfit`, the selection controls, turning snips into a
`data read` block, alternatives to `prepfit`, and notes for the dashboard.
Added step 0 to the Overview list, and bumped the doc to v0.4.

What I learned:

- `prepfit` writes **data files, not a model file**: one 4-column snip per
  transition (wave, flux, error, 0/1 mask), named
  `<stem>_<isotope+element>_<ion>_<λ0>_reg.dat`. The `data read` block is written
  by hand. The original §0 text said the output was a model file; this was corrected.
- If the parent spectrum has a fifth column, `prepfit` treats it as the
  continuum and multiplies the flux and error by it. Verified on J0814p5029:
  0.0789 × 2020.06 = 159.3. The snips are therefore un-normalised, and ALIS
  fits a local Legendre continuum per `specid`, with starting values at the
  local flux level.
- `w` writes every pixel within the current x-limits (±500 km/s by default), not
  just the selected pixels. The snip is also the only saved state, and is
  reloaded when a transition is revisited.
- Bugs and gaps confirmed in the code: the unsaved-changes warning on `q`
  never fires; `+`/`-` never update the Lyα overlay; `p` is unbound; the
  fine-structure filter never matches (confirmed by running `specplot.atomic`,
  which kept `I*`, `I**` and `II*` lines); line-ID drawing is unreachable; and
  the continuum column is inferred from the column count. These are listed
  in §0.6 as input to the dashboard design.
